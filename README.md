# AlfaHack: персональная новостная аналитика

FastAPI + PostgreSQL + отдельный worker. ML из предоставленной папки подключён
к HTTP API: профиль → извлечение факторов → граф → ранжирование → поиск
аналитики банка → интерпретация → проверка → инсайт с источниками.

## Быстрый запуск

Нужны Docker Engine и Compose v2. Создать `.env` из `.env.example`, если его
ещё нет, и задать случайные POSTGRES_PASSWORD / INGEST_API_KEY. В текущем
локальном checkout `.env` уже создан со случайными значениями и исключён из Git.

```sh
docker compose up --build -d
```

Compose поднимает PostgreSQL, применяет миграции, загружает синтетические demo-данные
и запускает API, worker и frontend. Для локального старта из чистого checkout не нужны
закрытые материалы кейса. Адреса доступны только локально:

- API / Swagger: http://localhost:8000/docs
- OpenAPI: http://localhost:8000/openapi.json
- Проверка готовности: http://localhost:8000/health/ready
- PostgreSQL: localhost:55432

Сайт: **http://localhost:5173**. Сначала зарегистрировать пользователя с компанией
из каталога. Готовых публичных логинов/паролей нет. Вход, профиль, новости,
задания, результаты, источники, вопросы и обратная связь подключены к API.

Frontend использует согласованный дизайн `frontend/design.md` и компоненты
Alfa Core Components. Запуск через Compose включает nginx с проксированием
`/api` и `/health`, поэтому браузер работает с одним origin.

### Быстрый запуск в текущем Windows checkout

Для этого checkout подготовлены `.venv`, локальная PostgreSQL в `runtime/`
и зависимости frontend. Из корня проекта:

```powershell
python scripts/dev.py
```

Команда запускает API, worker и frontend без отдельных окон, применяет миграции
и повторяемый импорт данных организаторов. Открыть http://127.0.0.1:5173.
Проверка: `python scripts/dev.py --status`. Остановка: `python scripts/dev.py --stop`.
Остановка сохраняет базу, аккаунты и анализы. Скрипт завершает только записанные
им процессы с совпадающим временем запуска. Для другого компьютера используйте
Compose либо ручной запуск ниже; portable PostgreSQL не входит в Git.

Подробнее: [frontend/README.md](frontend/README.md).

**Без ключа используется offline-режим по правилам**, с явной пометкой в ответе.
Он нужен для воспроизводимой проверки интерфейса, а не для имитации вызова LLM.
Внешние сервисы Neo4j/Qdrant/GLiNER для запуска не нужны.

## Локальная разработка без контейнера API

Python 3.12 и uv. Версии зависимостей зафиксированы в uv.lock.

```sh
uv sync --frozen
docker compose up -d db
uv run python -m backend.manage migrate
uv run python -m backend.bootstrap
```

В двух терминалах:

```sh
uv run uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --no-access-log
uv run python -m backend.worker
```

В третьем терминале:

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Vite проксирует запросы на `127.0.0.1:8000`. Настройки для другого адреса:
`frontend/.env.example`. Для просмотра сборки после `pnpm build` используйте
`pnpm preview`; proxy работает и в этом режиме. `dist/` в production обслуживает
nginx из `frontend/Dockerfile`.

DATABASE_URL из `.env` должен указывать на localhost:55432. Если пароль
содержит зарезервированные символы URI, его нужно URL-кодировать; сгенерированный
локальный пароль использует URL-safe символы.

Если предыдущая версия 001 уже применена вручную, migrate остановится без
разрушения данных. После проверки соответствия схемы можно выполнить:
`uv run python -m backend.manage migrate --baseline-001`.
Старые несовместимые варианты схемы автоматически не переделываются.

## Приватные материалы хакатона

Файлы в ml/data остаются локально и не входят в Git и Docker-образ.
Для полного импорта компаний, связей и платежей:

```sh
uv run python -m backend.manage import-data --with-payments
uv run python -m backend.manage import-bank
```

Пути по умолчанию — ml/data/classification_classes и
ml/data/alfa-bank_materials_for_large_business. Можно передать --folder.
Конфликтующие SYNTHETIC_U не склеиваются: сохраняется заглушка и приватный
runtime/import_report.json. Платежные снимки заменяются атомарно, а повторный
импорт одной версии не удваивает данные.

В контейнере материалы передаются отдельным read-only mount, например:

```sh
docker compose run --rm -v "$PWD/ml/data/alfa-bank_materials_for_large_business:/private-bank:ro" api python -m backend.manage import-bank --folder /private-bank
```

Демо поставляется с четырьмя полностью синтетическими профилями и тремя
синтетическими новостями. Реальная позиция банка появляется только после
импорта предоставленных Markdown-материалов. Неизвестные/конфликтующие даты
не угадываются; будущая или слишком старая аналитика не используется как
подтверждение события. На новом checkout приватные файлы нужно получить
разрешённым организаторами способом.

## Новые новости

POST /api/v1/ingestion/news принимает пачку до 50 статей с X-Ingest-Key.
[Пример тела](contracts/ingest-example.json). Ключ читает только серверный
сборщик, он не должен попадать в браузер. Сам ingest API не скачивает произвольные
адреса статьи: он получает текст и метаданные; отдельный RSS/Atom-сборщик читает
только явно настроенные оператором HTTPS-адреса лент.

Приём использует нормализацию, дедупликацию, NER и кластеризатор из ML-пакета.
Для RSS/Atom можно настроить `NEWS_FEED_URLS` как JSON-массив HTTPS-адресов лент
и вручную запускать `uv run python -m backend.manage collect-news`; перенаправления
не выполняются, размер каждой ленты ограничен 2 МБ, а за запуск обрабатывается не
более 50 публикаций. Автоматический расписанный запуск зависит от настроенного
оператором cron/планировщика.
Правила извлечения факторов консервативны: «ставка сохранена» не считается
её ростом. Для неподдерживаемого события offline-анализ честно пропускается.
Оператор может передать структурированные shocks; без них live-режим
пытается извлечь факторы разрешённой моделью. События сопоставляются между
поступлениями по датам, факторам и заголовкам; неоднозначное совпадение остаётся
отдельным. Идентичные публикации дедуплицируются между источниками и запусками.

## Разрешённая LLM

Настройки в локальном `.env`:

```dotenv
LLM_MODE=live
LLM_ALLOW_EXTERNAL=true
LLM_BASE_URL=https://changellenge.up.railway.app/v1
LLM_API_KEY=<private-key>
LLM_MODEL=qwen/qwen3.6-35b-a3b
LLM_ALLOWED_MODELS=["qwen/qwen3.6-35b-a3b"]
LLM_REASONING_EFFORT=none
LLM_MAX_TOKENS=3000
LLM_TIMEOUT_SECONDS=180
```

Deployment ID берётся у организаторов и должен соответствовать разрешённой
модели кейса: Gemma 4 26B A4B, GLM-5.3-Flash, Qwen3.6 35B A3B,
DeepSeek-V4.1-Flash, Qwen3-VL-30B-A3B-Instruct или Kimi-K2.6.
Не подставлять случайную модель провайдера. После изменения настроек
пересоздать api и worker: `docker compose up -d --force-recreate api worker`.

В live-режиме отправляется минимальный бизнес-контекст, без имени человека,
email, synthetic_u, выручки и платежей. Использовать только разрешённый endpoint
и материалы. При ошибке нет скрытой подмены ответа заглушкой: материал помечается
ошибкой, обработка остальных продолжается; если ошиблись все — задание получает failed. Живой сквозной сценарий с синтетическим профилем проверен на шлюзе
организаторов: извлечение факторов, инсайт и уточняющий вопрос с цитатами.
Настройки и безопасные коды ошибок: [docs/llm.md](docs/llm.md).
Повторная проверка подключения: `uv run python -m scripts.check_llm`.

## Проверка

```sh
uv run pytest ml/tests backend/tests/test_safety.py -q
TEST_DATABASE_URL='postgresql://<test-user>:<test-password>@localhost:55432/<test-db>' uv run pytest -q
uv run ruff check backend
uv run python scripts/check_secrets.py
uv run python scripts/smoke_api.py
```

TEST_DATABASE_URL задаётся явно. Интеграционные тесты создают отдельную временную
схему и удаляют только её. Роль БД должна иметь право CREATE SCHEMA.
Без этого параметра PostgreSQL-тесты пропускаются, что не считается их прохождением.
HTTP smoke требует уже запущенных API/worker и оставляет тестового пользователя
и результаты анализа; поэтому запускать на демонстрационной базе.

Проверка миграций и всего исходного импорта проведена на временной PostgreSQL 15.
Compose config проверен; полноценная сборка Docker требует работающего daemon.

## Архитектура и ограничения

- [Схема данных](docs/database.md)
- [Безопасность и границы](docs/security.md)
- [ML-модули и изменения](ml/README.md)
- [Сторонние компоненты](THIRD_PARTY_NOTICES.md)

Граф в текущем ML — граф макрофакторов, не доказанный граф поставок.
Платежи/связи сохраняются отдельно; само перечисление денег не доказывает
зависимость. Контекст связанных компаний влияет на оценку релевантности, но не
подменяет прямой финансовый ущерб и не доказывает причинность. Веса экспозиций
и факторного графа — эвристики, их нужно калибровать на разметке. Поиск аналитики
банка лексический по абзацам; новости ищутся полнотекстовым поиском PostgreSQL,
не векторным embedding RAG.
Проверка цитат и структуры не заменяет экспертную оценку всех выводов LLM.

Процесс измерения качества и команда метрик описаны в [docs/quality.md](docs/quality.md).
Сводный агрегированный отчёт для выбранного окна можно получить командой
`uv run python -m backend.manage quality-report --days 30`.

Для demo-регистрации можно выбрать любую обезличенную компанию. Для реальных
клиентов понадобится подтверждение полномочий. Текущий сервис не следует
открывать с реальными клиентскими данными в публичный интернет.

Датасеты исключены из текущего Git-индекса, но остаются в прежних коммитах.
До публикации репозитория отдельно проверить допустимость раскрытия его истории.

## Данные организаторов

По умолчанию Compose использует `DATA_MODE=demo`, чтобы запуск был воспроизводимым
без приватных файлов. Для режима организаторов установить `DATA_MODE=organizers`.
Тогда нужны оригинальные
`ml/data/classification_classes/df_Uid_data_hack.csv`, `df_Uid_payment_hack.csv`,
`df_Fid_Uid_link_hack.csv` и Markdown в `ml/data/alfa-bank_materials_for_large_business/`.
Seed получает их через read-only mount. Файлы исключены из Git и Docker image;
при отсутствии файлов запуск завершается с ошибкой, без подмены демо.
Повторный запуск пропускает импорт, если содержимое не изменилось.
Без файлов организаторов запуск в режиме `organizers` завершается ошибкой,
без подмены исходных данных демо-данными.

В профиле выбрать обезличенную компанию `U_…`. Старому аккаунту с демокомпанией
нужно сохранить этот выбор. Реальных названий/ИНН в исходном наборе нет.
Профиль, группы, платежные и общие персональные связи берутся из CSV автоматически.
Отсутствующие профили не выдумываются, конфликтующий профиль не выбирается случайно.
Платежи не доказывают поставку или зависимость. Повторные пары сохраняются как
исходные наблюдения без выдуманного суммирования. Доли платежей относятся только
к однозначным наблюдениям доступного набора, без предположения о периоде.

Граф обходится до 3 уровней по умолчанию (API максимум 4), максимум 32 компании,
до 5 соседей на вершину; вес пути ослабляется на каждом следующем уровне.
Профили связанных компаний локально оцениваются по факторам материала;
максимальный взвешенный косвенный сигнал добавляет до 0.2 к релевантности.
Это эвристическая оценка внимания, не прогноз убытка. Путь и ограничения видны в инсайте.
Внешняя LLM получает отрасли и агрегированный контекст связей, без идентификаторов
компаний/лиц и исходных сумм платежей.

В предоставленном наборе нет внешней новостной ленты: 9 обзоров банка доступны
как исходные аналитические материалы с соответствующей маркировкой. Внешние
новости можно передать защищённому ingest API или собирать из явно заданных
RSS/Atom HTTPS-лент командой `collect-news`. Даты, которые нельзя установить,
остаются неизвестными. Статус импорта: `GET /api/v1/data/status`;
связи: `GET /api/v1/me/counterparties`, граф: `GET /api/v1/me/connections?max_depth=3`.


## Обновление команды и проверка пачек

После `git pull origin main` проверить локальный `.env`: `DATA_MODE=organizers`,
`LLM_TIMEOUT_SECONDS=180`; остальные ключи хранить только локально. У каждого
развёртывания должны быть оригинальные файлы организаторов в `ml/data` — Git их
не передаёт. Запустить `docker compose up --build -d`, затем проверить
`/health/ready` и `/api/v1/data/status`. Существующий volume PostgreSQL сохранять;
Compose сам применяет миграции, а неизменившийся набор повторно не импортирует.

В интерфейсе выбрать компанию U_… и запустить 5 материалов. Каждый завершённый
инсайт появляется в ленте до окончания пачки. Прогресс и ошибки видны в карточке
задания; временная ошибка одного материала не отменяет остальные. Повторить
можно только неудавшиеся материалы. Реальные ошибки провайдера отображаются
без содержимого его ответа и без ключей. Для вопросов к готовому анализу proxy
ожидает до 400 секунд, клиент до 390: это учитывает один повтор запроса к LLM.
