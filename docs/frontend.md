# Подключение фронтенда

Базовый адрес локально: `http://localhost:8000`. Swagger: `/docs`.
Зафиксированный контракт: `contracts/openapi.json`; типизированный fetch-клиент:
`contracts/api.ts`. Его можно скопировать в приложение. Приватные ключи и URL
базы данных во frontend-переменные не передавать.

## Основной сценарий

1. `GET /api/v1/organizations?q=...` — публичный обезличенный каталог для демо.
2. `GET /api/v1/roles` — роли для селектора.
3. `POST /api/v1/auth/register` — email, пароль (10–128 символов), имя,
   role (`cfo`, `ceo`, `treasurer`, `chief_accountant`, `owner`), organization_id.
   Возвращает access_token. Повторный вход: `POST /api/v1/auth/login`.
4. На последующие запросы добавить `Authorization: Bearer <access_token>`.
5. `GET /api/v1/me/organization` — профиль и оценённые экспозиции.
6. `POST /api/v1/analyses` с `{ "max_events": 5 }` → HTTP 202, UUID задания.
   Кнопку на время запроса блокировать. Для безопасного повтора одного запроса
   использовать один и тот же `Idempotency-Key`; новый запуск — новый ключ.
7. Опрашивать `GET /api/v1/analyses/{id}` раз в 1–2 секунды до completed/failed.
8. После completed: `GET /api/v1/feed`. Пустая лента допустима — смотреть
   summary.skipped, не подменять её заранее подготовленной аналитикой.
9. `GET /api/v1/insights/{id}` — подробный результат с фактом, позицией банка,
   интерпретацией, действиями, трассой и цитатами.
10. `POST /api/v1/insights/{id}/questions` с `{ "question": "..." }`.
    В offline-режиме возвращается только существующее объяснение с явной
    пометкой об отсутствии свободного диалога. В live — ответ разрешённой модели.
11. `POST /api/v1/insights/{id}/feedback` с rating useful/not_useful/already_known,
    опционально comment. Сохраняется последняя оценка пользователя.
12. `POST /api/v1/auth/logout` отзывает текущий токен.

Пример:

```ts
import { AnalyticsApi } from './api';
const api = new AnalyticsApi('http://localhost:8000');
const catalog = await api.organizations('');
await api.register({ email, password, name, role: 'cfo', organization_id: catalog.items[0].id });
const job = await api.analyze({ max_events: 3 });
// В UI: таймер с очисткой при unmount, опрос api.job(job.id).
// После завершения:
const feed = await api.feed();
```

Токен держать в памяти приложения. Пример не пишет его в localStorage,
логи, URL или аналитику браузера. После обновления страницы нужен повторный вход.
Перед публичным размещением нужны HTTPS и ограничение регистрации; текущий
выбор компании пользователем рассчитан на обезличенный хакатонный каталог,
он не доказывает полномочия человека в реальной компании.

## Правила отображения

- `generation_mode=offline` — «Демонстрация: анализ по правилам, без LLM»;
  не подписывать такие ответы как результат вызова модели.
- `is_demo=true` — «Синтетический сценарий»; ссылки demo.invalid не открывать
  как настоящие новостные публикации.
- Факт, `bank_view` и интерпретацию показывать раздельно. `bank_view=null` —
  подходящая датированная аналитика не найдена, не генерировать её на фронте.
- `confidence` и `relevance_score` — эвристические оценки. Не переводить
  факторный индекс в проценты выручки, вероятность банкротства или рубли ущерба.
- Источники — из evidence, с датой и точной цитатой. Локальный source_ref
  открывается через `GET /api/v1/materials/{id}`, а не как файловый URL.
- Отрисовывать текст как текст; не использовать dangerouslySetInnerHTML для
  источников или LLM-ответов. Внешние ссылки разрешать только http/https.
- Лента сортируется по релевантности; пагинация — limit/offset. История повторных
  запусков может содержать несколько версий одного события.

## Ошибки

Форма: `{ "error": { "code": "..." } }`; при валидации есть fields с loc/msg/type.
401 — повторный вход; 403 — недопустимая операция; 404 — объект не найден/недоступен;
409 — повторный email, конфликт ключа или два незавершённых анализа;
413 — слишком большой запрос; 422 — проверить поля; 429 — подождать Retry-After;
502 — не удалось получить проверяемый ответ модели; 503 — база не готова.
Внутренние ошибки не содержат SQL, пароли или текст ответа провайдера.

## Другие эндпоинты

`GET/PATCH /api/v1/me` — профиль пользователя и смена должности;
`GET /api/v1/me/counterparties` — подтверждённые связи;
`GET /api/v1/materials?kind=news|bank_analytics` — материалы;
`GET /health/live`, `/health/ready` — проверки сервиса.

`POST /api/v1/ingestion/news` предназначен для оператора сбора новостей, а не
для браузера. Требует секретный заголовок X-Ingest-Key. Этот ключ нельзя
встраивать в JS bundle. Пример тела находится в `contracts/ingest-example.json`.
