# Защита данных в прототипе

## Что включено

- Внешние вызовы LLM выключены по умолчанию. Нет отправки в AI-сервисы
  по наличию ключа в домашнем каталоге, нет чтения `.nessy/settings.json`.
- Live-режим требует HTTPS, включённой проверки сертификатов, явного разрешения
  LLM_ALLOW_EXTERNAL, ключа, модели из фиксированного списка моделей хакатона
  и отдельного включения этой модели в LLM_ALLOWED_MODELS.
- В LLM не передаются email, имя пользователя, synthetic_u, выручка или платежи.
  Передаются текст события, отрасль, несколько признаков, роль и выдержки из
  аналитики. Это всё равно внешняя передача данных: включать только для
  разрешённого организаторами провайдера и разрешённых материалов.
- Пароли хешируются scrypt с отдельной солью. Сервер хранит SHA-256 токенов,
  срок жизни ограничен; logout отзывает текущую сессию.
- Авторизация проверяется на каждом запросе приватного задания/инсайта;
  пользователь не передаёт чужой user_id при создании анализа.
- Ингест отделён операторским ключом. API не загружает произвольные URL,
  не исполняет команды из документов и не даёт LLM инструмент shell.
- Логи содержат код ошибки, тип исключения, request_id/job_id. Не включены
  HTTP access logs с URL/параметрами, тела запросов и ответов провайдера.
- Ответы валидации не возвращают исходный пароль; ошибки сервера не раскрывают SQL.
- Ограничены тело запроса, пачки статей, размеры текста, количество анализов,
  частота авторизации/вопросов и число событий в задании.
- CORS разрешён только настроенным origin. Docker-сервисы опубликованы на loopback,
  приложение работает непривилегированным пользователем.
- `.env`, приватные данные, отчёты, IDE и ключи исключены из Git и Docker context.
  Проверка `scripts/check_secrets.py` включена локальным pre-commit hook.
  Проверяются и рабочие файлы, и staged blobs, включая точные совпадения
  с настроенными локальными секретами; значения секретов не выводятся.

## Границы

Этот прототип использует обезличенные компании. Регистрация с выбором компании
не доказывает, что пользователь является её представителем. Не загружать сюда
необезличенные клиентские данные и не открывать регистрацию наружу без
проверки членства, TLS и настроек эксплуатации.

Rate limiting работает в одном процессе API; для нескольких процессов нужен
общий лимитер на gateway/Redis. Хук не является DLP и не гарантирует обнаружение
секрета произвольного формата. Проверка цитат и полей не доказывает истинность
всех выводов LLM; требуется экспертная проверка качества.

CSV и материалы ранее уже находились в двух коммитах. Они убраны из текущего
индекса, но старые коммиты сохраняют содержимое. История не переписывалась,
никаких push/публикаций в рамках интеграции не выполнялось. Перед публикацией
репозитория отдельно решить, можно ли публиковать его существующую историю.

## Работа с секретами

Локальный `.env` создан с правами 0600 и случайными паролем PostgreSQL и ключом
ингеста, если этого файла ещё не было. Значения не выводились в лог и не
встроены в образ. `.env.example` содержит только шаблон.
Не отправлять `.env`, дампы БД, вывод `docker compose config` без `--quiet`
и логи провайдера в чат, скриншоты, Git или frontend-переменные.
Не коммитить live-ключи даже в приватный репозиторий.

Проверка перед коммитом: `python3 scripts/check_secrets.py`.
На другом checkout включить хук: `git config core.hooksPath .githooks`.
