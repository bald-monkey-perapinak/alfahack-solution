# Альфа-Бизнес — frontend

React + TypeScript + Vite + Alfa Core Components. Дизайн из `design.md` сохранён;
все поддерживаемые действия подключены к FastAPI `/api/v1`. Статических
компаний, новостей, выводов, ответов и имитаций обработки в приложении нет.

## Запуск

Текущий Windows checkout, из корня репозитория:

```powershell
python scripts/dev.py
```

Сайт: http://127.0.0.1:5173. Swagger: http://127.0.0.1:8000/docs.
Остановка: `python scripts/dev.py --stop`. Статус: `python scripts/dev.py --status`.
Логи — `runtime/dev-*.log`; база и настройки из Git исключены. Скрипт использует
уже подготовленную `.venv`, Node.js и PostgreSQL, ничего не скачивает. При
повторном запуске не создаёт второй свой worker; API и frontend с занятыми
портами не останавливает. `--no-seed` пропускает повторное заполнение демо.

На другом компьютере проще поднять весь проект из корня:

```sh
docker compose up --build -d
```

Перед этим настройте корневой `.env` по `.env.example`. Compose поднимает
PostgreSQL, миграции, seed, API, worker и frontend с nginx на localhost:5173.
Docker-сборка здесь не проверялась: на текущем компьютере нет Docker daemon.

Для отдельной разработки frontend при уже работающих API и worker:

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Node.js 22.18+ или 24+, pnpm 11.25.0. `pnpm build` создаёт `dist/`;
`pnpm preview` позволяет проверить сборку с API proxy.

## Адрес API

По умолчанию frontend обращается к своему origin. Vite и nginx проксируют
`/api/*` и `/health/*` к API. Никакие пароли БД и ключи LLM в браузер не передаются.

При необходимости скопируйте `frontend/.env.example` в `frontend/.env.local`:

```dotenv
API_PROXY_TARGET=http://127.0.0.1:8000
VITE_API_BASE_URL=
```

`API_PROXY_TARGET` используется только dev/preview-сервером. Для отдельного
публичного API можно задать `VITE_API_BASE_URL=https://your-api.example` при
сборке и разрешить origin frontend в `ALLOWED_ORIGINS` на сервере. В Compose
адрес upstream задан в `nginx.conf` как `http://api:8000`.

## Что подключено

| Экран / действие | API |
| --- | --- |
| Поиск компании, роли | GET organizations, GET roles |
| Регистрация, вход, выход | POST auth/register, auth/login, auth/logout |
| Профиль и смена роли | GET me, PATCH me |
| Компания и контрагенты | GET me/organization, me/counterparties |
| Новости и пагинация | GET materials?kind=news&limit&offset |
| Последние 1–10 или выбранные публикации | POST analyses с max_events и material_ids |
| Очередь и обработка | GET analyses/{uuid} |
| Готовая лента | GET feed?limit&offset; краткое содержание из insights/{id} |
| Подробный разбор и аудит | GET insights/{id} |
| Полный источник и точная цитата | GET materials/{id} |
| Уточняющий вопрос с источниками | POST insights/{id}/questions |
| Три варианта оценки и комментарий | POST insights/{id}/feedback |
| Режим сервиса | GET health/ready |

Банковский вход «через Альфа-Бизнес» остаётся честной заглушкой: такого API
в сервере нет. Обычные регистрация и вход работают с настоящими аккаунтами.
На новом аккаунте лента пустая до запуска анализа.

## Поведение данных и сессии

- Токен хранится только в памяти, как предписано `docs/frontend.md`. После
  перезагрузки нужен повторный вход; аккаунт, профиль, анализы и оценки
  сохраняются в БД. 401 и истечение сессии возвращают форму входа.
- В `sessionStorage` сохраняется только UUID последнего задания с ID пользователя,
  чтобы после повторного входа восстановить его статус. Токены, пароли и
  аналитические тексты туда не записываются. Явный выход удаляет UUID задания.
- POST запуска использует один `Idempotency-Key` на набор параметров. Повтор
  после сетевой ошибки безопасен: новый ключ появляется только для нового
  запуска или изменённых параметров. При выборе 10 новостей `max_events=10`.
- Опрос статуса идёт раз в 1,5 секунды, только до completed/failed. Каждый новый
  insight_id обновляет ленту сразу, ещё во время обработки пачки. При временной
  ошибке включается задержка, учитывается Retry-After. Запросы и таймеры очищаются
  при выходе. Работа продолжается при переходах между внутренними страницами.
- Пустой результат не подменяется карточками. Числа processed/created/skipped
  берутся из задания. Старые готовые выводы сохраняются при ошибке нового запуска.
- Лента сортируется сервером по релевантности. Confidence и relevance_score
  из диапазона 0–1 отображаются как проценты с пометкой об эвристике. Дата
  анализа отделена от даты публикации; даты показаны в часовом поясе Москвы.
- `is_demo` помечает только соответствующий материал или результат, а не весь сайт.
  demo.invalid и локальные source_ref не открываются как внешние ссылки.
- `bank_view=null` показывает отсутствие позиции банка. Цитаты и реальные даты
  берутся из evidence. Текст источников и ответов выводится безопасным текстом,
  включая многострочные цитаты, без HTML из входных данных.
- Вопросы доступны для live-анализа при работающем live-сервисе. В offline
  показывается существующее серверное объяснение с заблокированным полем.
  Интерфейс не включает LLM и не подменяет ошибку заранее созданным ответом.
- Имя и роль сохраняются через PATCH. При смене роли лента обновляется;
  подробный анализ сохраняет снимок роли и компании на момент его подготовки.

## Структура

`src/api/types.ts` — публичные DTO по OpenAPI; `client.ts` — запросы, отмена,
таймауты, 401 и нормализация ошибок. `hooks/useResource.ts` отвечает за загрузку,
`useAnalysisJob.ts` — за восстановление и опрос задания. `App.tsx` управляет
сессией, оболочкой и запуском. Экраны находятся в `src/pages`, просмотр источника —
в `components/SourceModal.tsx`. Общие интерактивные компоненты — Alfa Core Components.

## Проверки

```powershell
pnpm test
pnpm typecheck
pnpm build
```

Для реальной интеграционной проверки запустите локальные API и worker в режиме
offline и задайте адрес (можно использовать Vite proxy):

```powershell
$env:ALFA_TEST_API_URL = 'http://127.0.0.1:5173'
pnpm test
```

Этот тест создаёт отдельный синтетический аккаунт в демонстрационной базе,
проверяет сохранение профиля, обработку выбранной новости настоящим worker,
точные цитаты, обратную связь, выход и повторный вход. Без переменной тест
помечается SKIP, а не успешной проверкой API. Внешние LLM-вызовы в нём запрещены.

Backend-контракт: `../docs/frontend.md`, `../contracts/openapi.json`.
