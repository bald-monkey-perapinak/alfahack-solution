# Frontend: вход, новостная лента и профиль

Запускаемый прототип по `дизайн.md`, преимущественно разделам 2–4. Страница детального анализа из раздела 5 пока не реализована.

## Точка входа

При отсутствии демо-сессии сначала показывается экран по `profile_registration.md`: графитовая информационная колонка и белая форма, переключение «Вход / Регистрация», кнопка Альфа-Бизнеса. Маршруты `#/login` и `#/register` доступны напрямую. Внутренние разделы и боковое меню отображаются после демо-входа; первоначально запрошенный внутренний маршрут сохраняется. «Выйти из демо» находится в профиле и возвращает на вход.

**Это только демонстрационный шлюз, не авторизация и не защита данных.** Вход через Альфа-ID/Альфа-Бизнес — заглушка с поясняющим окном, без редиректов, импорта или запросов в банк. Служебные ссылки, поддержка и восстановление пароля также открывают поясняющие окна. Нет подтверждённых 2FA, сквозного шифрования, банковских протоколов или проверки корпоративного домена; в интерфейсе нет ложных индикаторов их подключения. Реальные персональные и банковские данные вводить нельзя.

Для демонстрационного входа заранее заполнены публичные данные `demo@example.com` / `DemoAccess2026!`. Другие данные не проверяются как реальные учётные записи. Регистрация проверяет введённые поля и создаёт один локальный демо-профиль, но не серверную учётную запись. Должность — свободный текст и здесь, и в профиле. Отрасль и размер штата выбираются из списков и сохраняются как необязательный контекст профиля. Поле «Компания / ИНН» принимает название или 10 цифр; по одному ИНН название не подставляется из вымышленного реестра. Телефон необязателен.

Пароли используются только в состоянии формы, не передаются в профиль, не сохраняются в браузерные хранилища и не отправляются на сервер. Пароль регистрации нужен лишь для проверки прототипа; при повторном входе используется указанная выше публичная демо-пара. В sessionStorage хранится только флаг демо-доступа со сроком до суток; при выборе «Запомнить демо-доступ на 30 дней» такой флаг хранится в localStorage. Выход удаляет оба флага, но не удаляет локальный профиль. Контекст компании пока не влияет на новости или скоринг.

Основные файлы: `src/pages/EntryPage.tsx`, `entry.css`, `src/lib/auth.ts`. Для настоящего входа нужны серверные регистрация/авторизация, безопасная сессия, восстановление доступа, утверждённые правовые документы, а затем интеграция Альфа-ID. Флаг demo в клиентском хранилище не заменяет эти механизмы.

## Профиль

### Навигация приложения

Общая шапка сохраняет профиль справа. Слева под шапкой — единая белая боковая панель «Лента новостей», «Избранное», «Анализ» с иконками Альфа-Банка и выделением активного раздела. На планшете 768–1023 px панель компактная, с иконками и доступными названиями; на телефоне становится горизонтальной полосой под шапкой, чтобы не сжимать контент. Сетка карточек учитывает фактическую ширину контента через container queries.

Маршруты: `#/` — лента, `#/favorites` — сохранённые новости, `#/analysis` — явно обозначенная заглушка будущих отчётов, `#/profile` — профиль. Переключатель «Все новости / Избранное» синхронизирован с боковым меню и историей браузера. Избранное сохраняется в состоянии приложения между разделами, но по-прежнему сбрасывается при обновлении страницы. Старые якоря `#news-id` открывают ленту.

Переход «Профиль» в общей шапке открывает `#/profile`. Hash-маршрут работает на статическом хостинге без дополнительных rewrite-правил. Страница профиля загружается отдельным JS-чанком; лента остается на `#/`, якоря `#news-id` поддерживаются.

Экран следует `profile_design.md`: две отдельные белые карточки, кнопка сохранения справа, сетка полей 1:1 и полноширинная должность, список контрагентов. Должность — обычный Input, без списка допустимых значений. По уточнению пользователя вместо фото — инициалы фамилии и имени; нет загрузки фото, камеры или статуса верификации. Используются установленные Core Components: Input, Button, IconButton, Icon View Circle, Typography, Toast и иконки `@alfalab/icons-glyph`. Во входной группе также используются Select (отрасль и штат), PasswordInput, PhoneInput, Checkbox, Tabs и Modal. Контейнеры и адаптивная сетка — CSS по спецификации. Высота полей 44px настроена CSS-токеном: API текущей библиотеки принимает size=48, но не 44.

- `src/pages/ProfilePage.tsx` и `profile.css`: форма, контрагенты и адаптивная верстка.
- `src/types/profile.ts`: типы профиля, должностей и контрагентов.
- `src/lib/profile.ts`: инициалы, нормализация, валидация и безопасное чтение локальных данных.
- `src/mocks/profile.ts`: демонстрационное наполнение, не данные реальных пользователей.

Форма проверяет ФИО, компанию, должность, e-mail и телефон. «Сохранить изменения» сохраняет личные данные. Добавление и удаление контрагентов сохраняются сразу, удаление можно отменить в уведомлении. Профиль и контрагенты хранятся раздельно в localStorage (`alfa-demo.profile.v1`, `alfa-demo.counterparties.v1`) только в текущем браузере; при поврежденных данных используются демо-значения. Это временное демо-хранилище, не механизм авторизации и не хранилище реальных персональных данных для production.

По ИНН проверяется только длина 10/12 цифр: реестра и проверки надежности нет, название организации не выдумывается. Новые контрагенты имеют общий тип «Контрагент», пока нет API или выбора типа связи. Профиль, должность и контрагенты пока не влияют на скоринг и новости. Для production нужны авторизация, серверный API профиля/контрагентов, поиск организаций и подключение персонализации. Несохраненный черновик полей сбрасывается при уходе со страницы.

## Запуск

Нужны Node.js 22.12+ (или совместимая более новая версия) и pnpm 11.

```sh
cd frontend
pnpm install
pnpm dev
```

Адрес: http://127.0.0.1:5173. Проверка типов: `pnpm typecheck`. Production-сборка: `pnpm build`. Тесты алгоритма компоновки: `pnpm test`.

## Раскладки

| Контейнер | Desktop от 1200 px | 768–1199 px | До 768 px |
| --- | --- | --- | --- |
| Hero | Вся ширина, фото 340 px | Вся ширина | Одна колонка, фото 16:9 |
| Duo | Две равные колонки, gap 20 px | Две колонки | Одна колонка |
| Trio | 1.4fr / 1fr; справа стек, gap 16 px | Главная сверху, две второстепенные ниже | Главная и второстепенные последовательно |
| Quartet | 2×2, gap 16 px; миниатюра 120×86 px | 2×2; миниатюра 96×86 px | Одна колонка |

Breakpoint-правила являются временным решением: документ не задаёт их точно. Порядок новостей внутри карточек и контейнеров сохраняется. У Trio первый элемент — главная новость; в desktop её высота совпадает с правым стеком. Главный экран использует buildNewsFeed: после поиска и фильтров новости автоматически группируются, компонуются и расставляются. Заголовок каждого раздела выводится один раз над всеми его контейнерами, пустые разделы скрываются.

## Главный экран

```ts
import { buildNewsFeed } from './src/lib/news-layout';

const sections = buildNewsFeed(filteredNews);
// [{ id, title, placement, topic?, count, containers: [...] }, ...]
```

NewsShowcase берёт плоский demoNews, применяет избранное, поиск, тему и срочность, затем передаёт результат в buildNewsFeed. Результат мемоизируется: открытие окна анализа и уведомления не пересобирает ленту. NewsFeedSection рисует один заголовок и счётчик материалов, а внутри — массив NewsContainer без повторных заголовков.

Последовательность разделов: «Срочные новости», «Самое главное», затем непустые темы в порядке массива topics. Темы назначены вручную полем topic: автоматической классификации текстов нет. Срочные собираются вместе из всех выбранных тем и используют общую компоновку Hero/Duo/Trio/Quartet, оставаясь только в urgent. Несрочные обрабатываются по каждой теме отдельно.

«Самое главное» имеет общий лимит maxHighlights на весь экран, по умолчанию 3. Кандидаты сначала отбираются в своих темах с учётом Hero-бюджетов, затем сравниваются по важности, дате и id. Не прошедшие общий лимит остаются Hero в своей теме; материалы не удаляются и не дублируются. После отбора каждая тема и срочная группа проходят arrangeNewsContainers.

В демо финансовый раздел содержит 14 материалов в шести контейнерах: Hero → Duo → Hero → Trio → Quartet → Trio; ещё один финансовый материал находится в «Самом главном». Срочный раздел содержит 5 материалов в Hero + Quartet.

## Автоматическая компоновка

```ts
import { composeNewsContainers, arrangeNewsContainers, getNewsImportanceStats } from './src/lib/news-layout';

const composed = composeNewsContainers(news, {
  groupId: 'economy',
  groupTitle: 'Экономика',
  policy: { heroRatio: 0.2, maxHeroCount: 3 },
});
const containers = arrangeNewsContainers(composed, { maxShift: 4 });

const urgent = containers.filter((item) => item.placement === 'urgent');
const highlights = containers.filter((item) => item.placement === 'highlights');
const regular = containers.filter((item) => item.placement === 'group');
const stats = getNewsImportanceStats(news);
```

Вход composeNewsContainers — `readonly News[]` одной полной исходной группы. `importance` обязателен: конечное число от 0 до 100. Выход — `ComposedNewsContainer[]`, совместимый с prop `group` существующего компонента NewsContainer. В каждом контейнере есть `id`, `title`, `variant`, `items`, а также `sourceGroupId` (исходная группа), `placement` и `reason`. Алгоритм не выбирает темы и не запрашивает API.

Правила по умолчанию:

1. Проверить уникальность непустых id, оценки и даты; отсортировать копию по важности, затем новой дате и id. Исходный массив и объекты не изменяются.
2. Разделить материалы на срочные (`urgency: 'urgent'`) и несрочные. Обе части используют один механизм Hero/Duo/Trio/Quartet. Все контейнеры срочной части имеют `placement: 'urgent'` и название «Срочные новости». Срочные никогда не попадают в «Самое главное» и не дублируются в основной группе; `planned` относится к несрочной части.
3. Отдельно для каждой части посчитать среднее, медиану и непересекающиеся категории: exceptional >= 95, high от 80 до 95, medium от 50 до 80, low < 50. Среднее диагностическое, медиана влияет на отбор обычных Hero. Hero-бюджет каждой части: `min(3, floor(N * 0.2))`, где N — количество материалов именно этой части. Сначала выбрать exceptional Hero в рамках бюджета. У несрочных они переходят в `placement: 'highlights'` («Самое главное») с ограничением maxHighlights. У срочных остаются в `placement: 'urgent'` с `reason: 'important'`; maxHighlights на них не влияет. Обе части независимо считают медиану и лимиты.
4. Дополнительные Hero выбираются из оставшегося начала массива при оценке >= `max(80, median + 10)` до исчерпания бюджета своей части. Если отбор оставляет одну новость, сократить его: сначала дополнительный Hero, затем exceptional Hero.
5. Две новости с оценками >= 50 и разницей <= 10 образуют Duo, если не остаётся одиночный хвост. В хвосте из четырёх обе пары должны удовлетворять этому правилу, иначе получится Quartet.
6. Для остальных предпочтителен Trio, если первая оценка выше второй на >= 10, иначе Quartet. Дополнительно проверяется остаток: для низких новостей не оставлять 2 или 5, когда доступно полное разбиение на тройки и четвёрки.
7. Остатки: 2 — Duo, 3 — Trio, 4 — Quartet (либо два сопоставимых средних Duo), 5 — Duo + Trio. Примеры низких групп: 6 = 3+3, 7 = 4+3 либо 3+4, 8 = 4+4, 9 = 3+3+3.

Явные исключения для обеих частей: единственная новость отображается Hero с `reason: 'single-item'`, если не выбрана как exceptional Hero. Для части из 2–4 материалов допускается один exceptional Hero сверх процентного лимита при включённых Hero; он отбирается только если после него остаётся минимум две новости. Поэтому [98, 10] останутся Duo. Несрочные [98, 30, 20] станут highlight Hero + Duo, а такие же срочные — Hero + Duo внутри urgent. `heroRatio: 0` или `maxHeroCount: 0` отключает акцентные Hero в обеих частях, но не техническое одиночное отображение единственного материала части.

`reason` объясняет выбор: highlight, important, balanced-pair, dominant-lead, compact, remainder или single-item. Срочность обозначается через placement, а reason показывает причину выбора формата. Первый элемент Trio всегда самый важный в нём. Каждый материал встречается ровно один раз. Порядок разделов в выходном массиве: urgent → highlights → group; внутри каждого сохраняется сортировка по важности, дате и id. Поэтому срочная новость с оценкой 10 окажется выше несрочной с оценкой 98, но может отображаться в компактном контейнере. Срочность сама по себе не гарантирует Hero.

Все пороги доступны через `policy` и экспортируемый `DEFAULT_NEWS_LAYOUT_POLICY`. Некорректные данные, повторные id и противоречивые настройки вызывают ошибку, а не молчаливую потерю материалов. Статистика пустой группы содержит `mean: null`, `median: null`. Публичная функция `getNewsImportanceStats(news)` считает статистику именно переданного массива; для статистики несрочной части передавайте `news.filter((item) => item.urgency !== 'urgent')`.

Ограничение области composeNewsContainers: `maxHighlights` применяется к одному вызову. Глобальный отбор между темами выполняет buildNewsFeed, подключённый к главному экрану. Для стабильной компоновки передавать полную группу, а не отдельную страницу API. Повторный вызов на отфильтрованном подмножестве считает бюджет и медиану уже по этому подмножеству; именно так сейчас работают фильтры экрана.

## Расстановка готовых контейнеров

`arrangeNewsContainers(composed, { maxShift: 4 })` работает после распределения новостей. Она возвращает новый массив тех же объектов контейнеров: не создаёт новые форматы, не меняет размеры, новости, id, placement или reason. Передавать нужно исходный результат composeNewsContainers, а не результат предыдущей расстановки: ограничение сдвига отсчитывается от входного порядка.

Примеры при настройках по умолчанию:

```text
Hero, Hero, Hero, Duo, Trio, Trio, Quartet
→ Hero, Duo, Hero, Trio, Hero, Trio, Quartet

Quartet, Quartet, Quartet, Duo, Trio
→ Quartet, Duo, Quartet, Trio, Quartet

Quartet, Quartet, Quartet
→ Quartet, Quartet, Quartet
```

Правила:

1. Обрабатывать отдельно каждый непрерывный участок с одинаковыми sourceGroupId и placement. Контейнеры не перескакивают через границы групп или между urgent, highlights и group. Подборка «Самое главное», состоящая только из Hero, останется неизменной.
2. Первый контейнер каждого участка закреплён — главный материал остаётся наверху. Для каждого формата поддерживается собственная очередь: более поздний Hero не обгоняет ранний Hero, аналогично для Duo, Trio и Quartet.
3. Выбор зависит от количества оставшихся форматов. Оценивать, какую минимальную длину серии одинаковых блоков потребует остаток после каждого кандидата. Это позволяет не расходовать редкие разделители сразу. При одинаковой оценке предпочитать меньший текущий повтор, затем более ранний блок исходного рейтинга.
4. Любой контейнер может переместиться максимум на maxShift позиций и вверх, и вниз. По умолчанию maxShift = 4; 0 отключает перестановки. Более важный ранний контейнер принудительно возвращается в выдачу при достижении предела задержки.
5. Полное чередование не гарантируется: других форматов может не быть, их может не хватить либо нужный контейнер находится за пределом maxShift. Алгоритм использует доступные блоки, не меняя уже принятое распределение новостей.

Важно: composeNewsContainers сохраняет строгую сортировку по важности внутри разделов. После arrangeNewsContainers важность частично уступает визуальному ритму: сохраняются первый блок, порядок внутри каждого формата и ограничение сдвига, но общей убывающей сортировки всех новостей больше нет. Это осознанное правило расстановки. Срочные материалы при любых перестановках остаются в urgent и не переходят в «Самое главное».

Тесты проверяют сохранность данных, независимость разделов, отсутствие мутаций, оба направления сдвига и порядок внутри форматов на 1000 группах. Для малых групп без ограничения перестановок длина максимальной серии дополнительно сверяется с независимым полным перебором вариантов.

## Демонстрационное поведение

Избранное хранится в состоянии React и сбрасывается при обновлении страницы. Кнопка анализа открывает подписанный предпросмотр, реальная генерация отсутствует. Тексты, даты и оценки ИИ вымышлены. Ссылки ведут на главные страницы источников, их нужно заменить ссылками конкретных публикаций. Фото загружаются с Unsplash; при отсутствии фото или ошибке отображается нейтральная заглушка. Шрифт — системный, Inter используется только если уже установлен. Полный заголовок Duo доступен через `title`; на touch-устройствах его можно прочитать в окне предпросмотра.

## Чтобы завершить карточки

1. Согласовать API новости и групп, подключить реальные тексты, ссылки публикаций и изображения.
2. Подключить сохранение избранного и реальный маршрут/запуск анализа, договориться о статусах очереди и ошибках. В типах и кнопке уже предусмотрены not_started, processing, ready, failed.
3. Добавить состояния загрузки, сетевой ошибки и повторного запроса при появлении API.
4. Определить методику рейтинга достоверности; убрать демонстрационные оценки.
5. Утвердить шрифт, breakpoint-правила, финальные размеры и визуально сверить с доступными оригинальными экранами Stitch. Сейчас источником служит только текст `дизайн.md`.
6. Перед публикацией заменить внешние демонстрационные фото на утверждённые ресурсы.

Примечание: у некоторых транзитивных зависимостей полной библиотеки Core Components устаревшие peer-диапазоны React (`react-popper`, `react-virtual`). Сам пакет поддерживает React 19. Для этой витрины проверяется сборка и фактическая работа используемых компонентов; перед внедрением других компонентов нужна проверка их совместимости. Скрипт установки `core-js` отключён: он выводит служебное сообщение и не нужен приложению.
