# ML-модули

Исходные модули и 144 теста перенесены из предоставленного news_analytics 2.
Код находится в ml/src, фикстуры для публичного демо — data/samples.
Главная интеграция с базой/API: backend/app/analytics.py и backend/worker.py.

Используются аудит данных, CompanyProfileBuilder, ShockPropagator, EventRanker,
InsightGenerator, InsightVerifier, NewsIngestor, NERExtractor и EventClusterer.
Аудит CSV и CLI отдельных модулей можно запускать с PYTHONPATH=ml/src.
Neo4j/Qdrant-адаптеры сохранены как опциональный исходный код; активное
хранилище приложения — PostgreSQL. Они не подключаются при старте API.

Изменения при интеграции:

- Оркестрация реализована собственным кодом, без LangGraph и готовой агентной системы.
- Полный набор компаний не профилируется заново для каждого HTTP-запроса:
  анализируется выбранный профиль из PostgreSQL.
- Ранжирование учитывает company_ids пользователя.
- Обход графа ограничен глубиной и исключает повтор вершины внутри пути.
  Тот же обход используется для суммарного вклада и объясняющих путей.
- Уверенность учитывает профиль и глубину пути; она не калибрована как вероятность.
- Календарная разница дат считается datetime, а не приближением 365/30 дней.
- NER по умолчанию использует локальные правила, без загрузки GLiNER/torch.
- Старый LLM-клиент с чтением ~/.nessy и отключением TLS заменён адаптером,
  использующим явную конфигурацию сервера.
- Внешние и локальные материалы сохраняются с первоисточниками, а позиция
  банка формируется из точных найденных абзацев, отдельно от AI-вывода.
- Сервер заменяет небезопасные шаблонные заявления о фиксации ставок и
  гарантированном эффекте нейтральными действиями по проверке договоров.

Offline-режим детерминирован и явно обозначен; live требует разрешённого
провайдера и явного согласия на внешнюю передачу. Описание запуска и API —
в корневом README и docs/frontend.md.

Качество исходных эвристик не измерено на экспертной разметке. Имеющиеся
тесты проверяют поведение программы, а не доказывают бизнес-эффективность.
